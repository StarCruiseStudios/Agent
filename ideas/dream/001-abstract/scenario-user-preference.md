# Scenario: A user preference kept in its place

**Layer:** 001, Abstract
**Status:** Proposed

This scenario is illustrative. It shows principles 6, 8, and 9 at work.

---

In several sessions across two projects, the user corrects agents that write long commit messages and asks for a one-line summary instead. The user also gives Archon a note saying that this applies to all of their work.

Archon proposes a practice for commit messages and classifies its origin as a user preference that holds for all of the user's projects (principle 9). The note is kept exactly as written and cited alongside the corrections (principle 6). The practice prescribes how agents work, so it is kept apart from memory that describes how either project works (principle 8). The practice is never presented to agents as a general rule for all software work, because nothing in the evidence shows that it holds regardless of who is doing the work.
